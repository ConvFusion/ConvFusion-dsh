# Skill: Sync

## Purpose

把一份**下载下来的研究工作区快照（ZIP）**安全地并入本工作区：同一项研究就**融合**，
另一项就**先备份再换成新的**，判不出来就先只读盘查再判断 —— 永远两步走、永远不静默覆盖。

## When to Use

Use this skill when:

- 用户发出 `/research sync @某.zip`（或 `/research 同步 @某.zip`）之后 —— 这是它的主入口；
- 用户说"把刚下载的工作区同步进来 / 合并这个快照 / 用它替换当前研究"时；
- 你自己发现工作区根上躺着一份**下载下来的研究快照 ZIP**（与 `workspace/` 平级），
  而用户的目标是让这项研究吸收它。

**不适用**：不是研究工作区快照的普通压缩包（例如数据集附件）；那种情况按用户的具体要求处理。

## Inputs

命令会把本次同步的参数一并给出。**缺哪一项就自己查，不要瞎猜**：

| 参数 | 含义 | 缺了怎么办 |
|---|---|---|
| 压缩包 | ZIP 的绝对路径（已校验存在且完整） | 必填；没有它就不要开始 |
| 本工作区 / 研究根 | 会话工作区，以及研究数据所在的研究根（新布局 = `<工作区>/workspace`） | 用 `researchWorkspaceOf` 的口径自己判断 |
| 现场判定 | `new` / `same` / `other` / `unknown` / `unverifiable` | **按第 1 步盘查后自己给判断**（等于 `unknown` 那一支） |
| 本机身份 | `<研究根>/.convfusion/work.json`（这项研究的标识） | 读一下；读不到就按"读不到标识"处理 |
| 服务器标识 | 下载时记录的 `workspace_id` / 项目 id / 服务器地址 | 没有就不比较标识，改用主题比对 |
| 备份名建议 | 备份目录名的一个起点 | 按下面的规则自己取一个更准的 |

## Research Method

**两步走，中间必须停一次。** 第 1 步一个字节都不要动。

### 第 1 步 · 只读盘查（不要改动、不要创建、不要删除任何文件）

把压缩包内的文件清单（相对路径 + 大小）与研究根现有文件对照，分成四类逐条列出：

1. **仅包内有**（会新增）—— 列出全部；
2. **仅本地有**（必须原样保留）—— 列出全部；
3. **两侧都有、内容相同**（无需处理）—— 只报数量；
4. **两侧都有、内容不同** —— 逐个给出：路径、两侧大小与修改时间、类型（文本 / 结构化 /
   二进制 / 机器生成物），以及一句话说明"差在哪"。

**报告完请停下来等用户确认，不要继续第 2 步。**

### 第 2 步 · 按判定执行（用户确认后）

#### A. `same` —— 同一项研究：**就地融合**（不是覆盖）

对第 4 类的每个文件，先读两侧内容，再产出一份**融合后的新文件**：

- **文本 / 结构化**（`.md`/`.tex`/`.json`/`.yaml`/`.csv`…）：两侧信息都必须保留。不是拼接，
  而是按这个文件的语义合并（research-state 按维度合并、plans 按计划项去重合并、
  论文按章节合并、证据 / 主张 / 文献列表取并集去重）。
- **同一个结论互相冲突**（不能同时成立）：不要替用户决定、不要丢掉任何一侧 ——
  把冲突原样列进报告，并在文件里保留可辨识的两说，等用户裁决。
- **二进制 / 媒体**（图、PDF、压缩包…）：语义上无法融合 —— 保留修改时间较新的一份在原处，
  另一份**移到** `<研究根>/.convfusion/incoming/<时间戳>/<原相对路径>`（**不删除**），
  并在报告里给出两侧的修改时间。时间戳用 `YYYY-MM-DDTHH-MM-SSZ`（冒号换 `-`，
  Windows 与各类 ZIP 工具都不接受文件名里有冒号）。
- **机器生成物**（缓存 / 依赖 / 构建产物 / 备份）：跳过，只在报告里列一行。

第 1 类（仅包内有）直接写入研究根（保持包内相对路径）；第 2 类（仅本地有）一律不动。

#### B. `new` —— 本工作区还没有研究根：**解压成新的研究根**

把包内文件按相对路径解压到研究根（`<工作区>/workspace`），保持包内相对路径。
这一支没有旧研究根可备份，所以**不需要备份**。

#### C. `other` —— 本工作区里是**另一项**研究：**先备份，再换成新的**

1. **备份**（移动，不是删除）：把现有研究根**整体移到本工作区根下**的备份目录
   —— 与研究对象同级，别放进研究根里面。用**移动**而不是复制，这样新研究根从零开始；
   备份必须留在原地、随时可恢复。
2. **取名由你取**（避免同名）：**前缀固定 `workspace_`**，后面接
   **研究主题 / 方法的首字母缩写**与**日期**，形如 `workspace_LHRDP_20261011`；
   缩写以工作区里 `project.md` 的主题 / 方法为准。**同名就加 `-2`、`-3`**
   （别覆盖上一次的备份）。
3. **解压**：把包内文件按相对路径解压到研究根（`<工作区>/workspace`）。
4. 备份目录里原有的东西一个都不要改、不要删。
5. 在报告里给出**备份目录的最终名字**（用户以后要靠它找回旧研究）。

**旧布局**（研究数据直接在工作区根，没有 `workspace/` 子目录）时：备份只搬**研究数据**
（`project.md`、`research-state.md`、`plans/`、`research/`、`papers/`、`experiments/`、
`outputs/`、`attachments/`）—— 用户自己的材料（原始论文、数据集、笔记等）留在原处不要动。

#### D. `unknown` / `unverifiable` —— 判不出来：**先给判断，等确认**

先在报告里给出判断（**同一项 / 另一项**）与依据（对照两侧 `project.md` /
`research-state.md` 的研究主题与研究问题），**等用户确认**，再按 A 或 C 执行。

两种情况下都不要删除任何一侧的内容。

### 身份文件（研究工作的标识）

研究根里有一个身份文件 `<研究根>/.convfusion/work.json`：换机器、被复制之后靠它自证身份。

- **判定为 `same` 时才写**（内容与字段以命令给出的为准，`snake_case`）：
  `workspace_id` / `project_id` / `server_url` / `role` / `synced_at`，并在报告里给出最终内容。
- 判定为 `other` / `unknown` / `unverifiable` 时**不要写** —— 写下去会把两项研究认成一项。
- 命令没给服务器标识时跳过这一步，并在报告里说明"服务器未提供标识，未写身份文件"。

### 边界

- 只改动**本工作区以内**的内容；压缩包**不要删**（它是用户下载下来的原始快照）；
  其它路径一概不动。
- 不替用户裁决结论冲突，不静默覆盖任何一侧。
- 全程**不要**主动发送消息、不要调用任何提交 / 推送动作。

## Evidence Requirements

- 第 1 步的**四类清单**必须完整（第 1、2 类逐条列出，第 3 类只报数量，第 4 类逐条给差异说明）。
- 第 2 步的**逐文件处置表**：新增 n / 融合 m / 内容相同跳过 k / 仅本地保留 j /
  二进制取新 b / 备份 b / 生成物跳过 c。
- 备份过就**必须给出备份目录的最终名字**；写过身份文件就给出它的最终内容。
- 未能裁决的冲突必须原样列出（不隐藏、不合并成一说）。

## Expected Output

1. **第 1 步**：一份只读盘查报告（四类清单），然后停下等确认。
2. **第 2 步**（确认后）：一次执行 + 一份执行报告 ——
   逐文件处置表、融合 / 替换的每个文件各一句话、备份目录名、身份文件内容、
   未裁决的冲突清单。
